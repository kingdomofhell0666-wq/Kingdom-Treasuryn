🧠 CORE IDEA
━━━━━━━━━━━━━━━━━━━

Admins create missions.

Missions are posted automatically in a fixed channel.

Users interact ONLY through buttons.

Missions can include:
- time limits (expiration)
- participant limits (slots)
- rank restrictions (VIP)
- paid entry (DC cost)

Admins validate completion.

Users are paid automatically from Treasury.

⏱️ TIMER / EXPIRATION
━━━━━━━━━━━━━━━━━━━

Support durations:
- 10m, 1h, 24h, 3d

Store:
expires_at

Rules:
- expired missions cannot be accepted
- expired missions cannot be completed
- buttons must be disabled after expiration

When expired:
- update message:
"This mission has expired."

━━━━━━━━━━━━━━━━━━━
👥 SLOTS SYSTEM (LIMITED MISSIONS)
━━━━━━━━━━━━━━━━━━━

If max_participants is defined:

- track accepted users
- once limit reached:
  → block new accept
  → message:
  "This mission is no longer available."

━━━━━━━━━━━━━━━━━━━
👑 VIP SYSTEM (RANK RESTRICTION)
━━━━━━━━━━━━━━━━━━━

If required_rank is defined:

On Accept:
- check user rank
- if user rank < required_rank:
  → deny
  → message:
  "You are not worthy of this task."

━━━━━━━━━━━━━━━━━━━
💰 PAID ENTRY SYSTEM
━━━━━━━━━━━━━━━━━━━

If entry_cost is defined (>0):

On Accept:
- check wallet ≥ entry_cost
- subtract DC from user wallet (REAL DB)
- add DC to Treasury (REAL DB)
- log transaction

If insufficient funds:
→ deny

━━━━━━━━━━━━━━━━━━━
🔘 BUTTON LOGIC
━━━━━━━━━━━━━━━━━━━

On Accept:

Check in order:

1. mission exists
2. not expired
3. slots available
4. rank requirement satisfied
5. user not already accepted
6. if entry_cost:
   - verify funds
   - deduct
   - transfer to Treasury

If all pass:
→ register user

If any fail:
→ deny with appropriate message

━━━━━━━━━━━━━━━━━━━
👑 ADMIN VALIDATION
━━━━━━━━━━━━━━━━━━━

/mission complete user:<@user> id:<mission_id>

Must:

- verify mission exists
- verify mission active
- verify not expired
- verify user accepted mission
- mark completed
- trigger payment

━━━━━━━━━━━━━━━━━━━
💰 REWARD PAYMENT
━━━━━━━━━━━━━━━━━━━

On completion:

- remove DC from Treasury (REAL)
- add DC to user wallet (REAL)
- commit DB changes

If Treasury insufficient:
→ reject
